## 3. Блок-схема и принцип работы системы

Устройство состоит из трех функциональных узлов:
1. **Делитель частоты (`count_div2`)**: понижает частоту встроенного генератора платы DE1-SoC с 50 МГц до 1 Гц (1 такт в секунду).
2. **Сдвиговый регистр (`shift_reg`)**: содержит 6 параллельных 4-битных регистров (`WIDTH=4`, `DEPTH=6`). По каждому положительному фронту сигнала 1 Гц входные 4 бита с тумблеров `SW[3:0]` записываются в нулевую ячейку, а значения всех остальных ячеек сдвигаются на одну позицию вправо: `shift_reg[i] <= shift_reg[i-1]`.
3. **Шесть семисегментных декодеров (`coder` / `coder_hello`)**: преобразуют 4-битный код из каждой ячейки регистра в 7-битный сигнал управления сегментами индикаторов `HEX0..HEX5`.

### Схема взаимодействия блоков:

```
[ CLOCK_50 (50 МГц) ] ----> [ count_div2 ] ----> clk_1hz (1 Гц)
[ reset (KEY[0]/SW[9]) ] ------+----------------------+
                               |                      |
[ SW[3:0] (число) ] ---------> |                      v
                               +---------------> [ shift_reg ]
                                                 |  |  |  |  |  |
                                                 q0 q1 q2 q3 q4 q5 (каждый по 4 бита)
                                                 |  |  |  |  |  |
                                                 v  v  v  v  v  v
                                              [coder][coder]...[coder]
                                                 |  |  |  |  |  |
                                                 v  v  v  v  v  v
                                                HEX0 HEX1 HEX2 HEX3 HEX4 HEX5
```

> **Порядок движения на индикаторах:**
> На плате DE1-SoC индикаторы физически расположены слева направо: `HEX5 - HEX4 - HEX3 - HEX2 - HEX1 - HEX0`.
> Новое число поступает в ячейку `q0` (индикатор `HEX0` — крайний правый). При следующем такте оно сдвигается в `q1` (`HEX1`), затем в `q2` (`HEX2`) и так далее до `HEX5`.
> Таким образом, на индикаторах реализуется классический эффект **«бегущей строки» справа налево**.

## 4. Подробное объяснение каждого модуля

### 4.1. Сдвиговый регистр (`shift_reg.v`)

Модуль спроектирован в точном соответствии с образцом в методичке (страница 24, Рис. 4.3):

```verilog
module shift_reg
#(
    parameter WIDTH = 4,    // Разрядность одной ячейки (4 бита)
    parameter DEPTH = 6     // Количество стадий сдвига (6 индикаторов)
)
(
    input  wire             clk,      // Тактовый сигнал (1 Гц)
    input  wire             reset,    // Асинхронный сброс
    input  wire [WIDTH-1:0] data_in,  // Входное число с тумблеров SW[3:0]
    output wire [WIDTH-1:0] q0,       // Выход на HEX0
    output wire [WIDTH-1:0] q1,       // Выход на HEX1
    output wire [WIDTH-1:0] q2,       // Выход на HEX2
    output wire [WIDTH-1:0] q3,       // Выход на HEX3
    output wire [WIDTH-1:0] q4,       // Выход на HEX4
    output wire [WIDTH-1:0] q5        // Выход на HEX5
);
```

#### Разбор внутренней логики:
1. `reg [WIDTH-1:0] shift_reg [DEPTH-1:0];`
   Объявляется массив из 6 регистров по 4 бита. В памяти синтезируются 24 D-триггера ($6 \times 4$).
2. `assign q0 = shift_reg[0]; ... assign q5 = shift_reg[5];`
   Каждая ячейка непрерывно соединяется со своим выходным портом.
3. Процесс сдвига:
   ```verilog
   always @(posedge clk or posedge reset)
   begin
       if (reset)
       begin
           for (i = 0; i < DEPTH; i = i + 1)
               shift_reg[i] <= {WIDTH{1'b0}};
       end
       else
       begin
           for (i = 1; i < DEPTH; i = i + 1)
               shift_reg[i] <= shift_reg[i-1];
           shift_reg[0] <= data_in;
       end
   end
   ```
   * **При `reset = 1`:** цикл `for` асинхронно записывает нули во все 6 ячеек.
   * **При `posedge clk`:** неблокирующие присваивания (`<=`) выполняются параллельно:
     - `shift_reg[5]` принимает предыдущее значение `shift_reg[4]`;
     - `shift_reg[4]` принимает предыдущее значение `shift_reg[3]`;
     - ...
     - `shift_reg[1]` принимает предыдущее значение `shift_reg[0]`;
     - `shift_reg[0]` принимает свежее значение со входа `data_in`.

### 4.2. Делитель частоты (`count_div22.v`)

Кварцевый генератор на плате DE1-SoC имеет частоту $F_{in} = 50\text{ МГц} = 50\,000\,000\text{ Гц}$ (период $T = 20\text{ нс}$).
Для человека такой сигнал слишком быстрый. Чтобы наблюдать сдвиг визуально, требуется частота $F_{out} = 1\text{ Гц}$ (период 1 секунда, полупериод 0.5 секунды).

#### Расчет коэффициента деления $M$:
$$T_{out} = 1\text{ с} \implies T_{half} = 0.5\text{ с}$$
$$M = \frac{0.5\text{ с}}{20\text{ нс}} = \frac{0.5}{20 \times 10^{-9}} = 25\,000\,000$$

Разрядность счетчика $N$:
$$2^{24} = 16\,777\,216 < 25\,000\,000 < 2^{25} = 33\,554\,432$$
Следовательно, требуется минимум 25 бит. Мы задаем $N = 26$ с запасом:
`parameter N = 26; parameter M = 26'd25_000_000;`

#### Логика работы:
* Внутренний счетчик `cnt` инкрементируется каждый такт $50\text{ МГц}$.
* Когда `cnt == M - 1` (через 25 миллионов тактов), счетчик сбрасывается в `0`, а выходной сигнал `sync` инвертируется (`sync <= ~sync`).
* В результате `sync` находится в состоянии '1' 0.5 секунды и в состоянии '0' 0.5 секунды. Полный период составляет ровно 1.0 секунду (1 Гц).
* **Внимание для симуляции:** В тестбенчах параметр $M$ переопределяется на `M = 4`, чтобы симуляция не занимала миллионы тактов, а выполнялась за микросекунды.

### 4.3. Семисегментный декодер цифр (`coder.v`)

Индикаторы на плате DE1-SoC имеют схему с **общим анодом**:
* `0` — сегмент зажигается (ток течет через светодиод на землю).
* `1` — сегмент погашен.

Расположение сегментов `seg[6:0]`:
```
      a (seg[0])
     ---
  f |   | b (seg[1])
(seg[5])|
     ---  g (seg[6])
  e |   | c (seg[2])
(seg[4])|
     ---
      d (seg[3])
```

Таблица кодирования:
* `0` $\to$ `7'b1000000` (горят все кроме g)
* `1` $\to$ `7'b1111001` (горят только b и c)
* `2` $\to$ `7'b0100100` (горят a, b, g, e, d)
* `3` $\to$ `7'b0110000`
* `4` $\to$ `7'b0011001`
* `5` $\to$ `7'b0010010`
* `6` $\to$ `7'b0000010`
* `7` $\to$ `7'b1111000`
* `8` $\to$ `7'b0000000` (горят все сегменты)
* `9` $\to$ `7'b0010000`
* `A`..`F` $\to$ шестнадцатеричные символы.

### 4.4. Декодер фразы «HELLO FRIEnd» (`coder_hello.v`)

Для пункта 6.б методички требуется вывести фразу **HELLO FRIEnd**.
На 7-сегментном индикаторе некоторые буквы невозможно отобразить заглавными без путаницы:
* Буква `D` в заглавном виде неотличима от `0` (O), поэтому её отображают строчной: `d` (`seg = 7'b0100001`).
* Буква `R` заглавной не формируется, её отображают строчной: `r` (`seg = 7'b0101111`).
* Буква `N` заглавной сливается с `H`, поэтому отображается строчной: `n` (`seg = 7'b0101011`).

Именно поэтому в методичке фраза записана как: **HELLO FRIEnd**.

#### Таблица соответствия кодов в `coder_hello.v`:
| Код на входе | Буква | Горящие сегменты | Код `seg[6:0]` |
| :---: | :---: | :---: | :---: |
| `4'd0` | **H** | b, c, e, f, g | `7'b0001001` |
| `4'd1` | **E** | a, d, e, f, g | `7'b0000110` |
| `4'd2` | **L** | d, e, f | `7'b1000111` |
| `4'd3` | **L** | d, e, f | `7'b1000111` |
| `4'd4` | **O** | a, b, c, d, e, f | `7'b1000000` |
| `4'd5` | *(пробел)* | все выключены | `7'b1111111` |
| `4'd6` | **F** | a, e, f, g | `7'b0001110` |
| `4'd7` | **r** | e, g | `7'b0101111` |
| `4'd8` | **I** | b, c | `7'b1111001` |
| `4'd9` | **E** | a, d, e, f, g | `7'b0000110` |
| `4'd10` | **n** | c, e, g | `7'b0101011` |
| `4'd11` | **d** | b, c, d, e, g | `7'b0100001` |

### 4.5. Результирующие модули (`main.v` и `main_hello.v`)

Модуль `main.v` объединяет всю систему:
1. Создает экземпляр `count_div2 div_inst`: делит `clk` (50 МГц) до `clk_lw` (1 Гц).
2. Создает экземпляр `shift_reg sreg_inst`: работает от `clk_lw`, сдвигает данные с `data_in`.
3. Создает шесть экземпляров `coder dec0..dec5`: преобразуют состояния выходов `q0..q5` в управляющие сигналы индикаторов `hex0..hex5`.
4. Сигнал `clk_1hz` выведен наружу — его можно назначить на светодиод `LEDR[0]`, чтобы видеть мерцание тактов с частотой 1 Гц.

Модуль `main_hello.v` устроен полностью аналогично, но вместо `coder` использует `coder_hello`.
